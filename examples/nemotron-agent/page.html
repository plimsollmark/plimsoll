Signed proof of what a Nemotron coding agent ran

An NVIDIA Nemotron model on Nebius Token Factory was given a task and one tool: run code in a plimsoll sandbox. Every run it made left a run record (the daemon's statement of what was sent, what came back and where it ran, as SHA-256 digests), signed by a harness (a signing program outside the daemon) into the bundle beside this page. Anyone can recheck the bundle offline with the public key. The agent's answer is below; the evidence is what it rests on.

Check it yourself

The bundle (bundle.jsonl) and the public key (harness.pub) sit beside this page. From a clone of the repository:

go run ./cmd/plimsoll-attest verify -pub harness.pub bundle.jsonl

That recomputes every record's digests from the stored request and response, checks every signature and the session's chain (call {{.Calls}} closes it), and refuses the bundle if one byte of any run was changed or one call was dropped. The same program replays the session into a fresh sandbox:

go run ./cmd/plimsoll-attest replay -daemon http://127.0.0.1:8746 -pub harness.pub bundle.jsonl

Verify in your browser

The same verification, compiled to WebAssembly (about 3.7 MB the first time, decompressed in the page): every record's digests recomputed from the stored request and response, every signature, every link and the session's chain. The bundle and the key never leave your browser. The second button changes one byte of a stored response first, so you can see the refusal.

How it was made

The program is examples/nemotron-agent in the plimsoll repository. It starts plimsolld on the docker provider under gVisor with the Python image, opens one session, and gives the model the task and the run_code tool. The model's code runs in the session; the result goes back to the model; the harness signs each exchange as the client makes it, and the session's close is signed with the count of calls. Nothing the page states about a run comes from the model: it comes from the daemon's answer, checked by the client, and signed.
