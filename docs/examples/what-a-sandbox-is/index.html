What a sandbox is

Someone hands you a program and says "run this for me". You did not write it, and you are not going to read all of it. It is probably fine. Most code is. This page is about the rest, and about how plimsoll tells you which precautions a given run actually got.

Running code you did not write

A program you run acts as you. It can read the files you can read, send what you can send over the network, and use as much memory and time as the machine will give it. That is the deal with every program on your computer, and it works because you chose those programs.

More and more code comes from nobody you chose. An AI agent, a program that uses a language model to decide what to do next, writes a few lines to answer a question and wants them run. The model may simply be wrong. It may have read a web page with instructions planted in it, a trick called prompt injection: instructions hidden in data a model reads, written so that the model follows them. Either way, the code that arrives is a stranger's code, and you are about to let it act as you.

A sandbox is a place where code runs with something stopping it from reaching the rest of the machine. Think of a room in your house set aside for a visitor: you let the stranger in, but only into that room, and the door locks from the outside. plimsoll's documentation even calls the stranger's code the guest: the code running inside a sandbox, seen from the machine that runs it.

Rooms differ in their locks, and that is the whole subject of this page. plimsoll calls the strength of the lock the isolation tier: how strong the wall around a run is, one of four levels, weakest first: process, container, kernel, vm. plimsoll does not build the rooms itself. It is the doorman in front of them: it checks each request, sends it to the one kind of room it was set up with, and writes on every answer which kind of room that was.

Five strangers in the cheapest room

On 2026-11-05 a plimsoll server, plimsolld, was started on a laptop with the setting SANDBOX_PROVIDER=wasm. The provider is the backend that actually runs the code, and each server uses exactly one. wasm is the cheapest room plimsoll has: JavaScript runs on QuickJS, a small JavaScript engine, compiled to WebAssembly, a portable bytecode format that runs inside a host program, which decides everything the code can reach. Here the host program is plimsolld itself.

Five short JavaScript programs were sent to it, four of them behaving the way a badly behaved stranger might, and a sixth from a careful caller. What each card shows came back from the server unedited; it is read from the signed recording published beside the next page (INTERNAL · plimsoll site →), which also shows how to check it.

What this room does not stop

  
Every stranger above was stopped by the engine. But the engine runs inside plimsolld, the
  plimsoll server's own program. A stranger who found a bug in QuickJS or in the WebAssembly
  runtime could make an escape, a bug that lets code inside a sandbox act outside it,
  and it would land inside plimsolld, with plimsolld's permissions. That is why this room's tier
  is called process, and why plimsoll's own documentation says not to point it at
  hostile code. It is for speed and for development: the first three runs above took

Four rooms, four locks


Each provider restricts memory, run time, files and network access. For providers whose walls
depend on the host or a remote service, a startup test checks the promised restrictions; the
in-process wasm provider relies on the project's own tests. (A run can be given one narrow exception, a
grant: permission, attached to one run, for its code to call listed routes of one
HTTP API through plimsoll, which adds the credential itself, so the code never sees it.) Where rooms
differ is what happens when the lock itself has a bug. The picture puts each room where its
escape would land.






  

    
The playpen

    
Tier process · provider wasm

    

      
What it is
A playpen in your living room. QuickJS runs inside plimsolld's own program, behind the walls the WebAssembly engine draws: no files, no network, a hard memory cap, a deadline.

      
If the lock breaks
The stranger is loose in your living room: inside plimsolld, with its permissions. There is no operating-system wall at all.

      
Runs
One JavaScript snippet at a time. No files, packages or build steps.

      
For hostile code?
no Fast and free, for code you mostly trust.

    

  

  

    
The spare room

    
Tier container · providers docker under runc, openshell, agentsandbox under runc

    

      
What it is
A spare room with its own lock, sharing the house's wiring. A container is a process started with its own view of files, network and other processes, while still sharing the machine's kernel. Docker's default runtime, runc, builds those walls with the kernel's own features. plimsoll's docker room adds a read-only root, small writable areas held in memory where a written file cannot be started as a program by its path, no network but the container's own loopback (a connection only to itself), and root's special powers taken away.

      
If the lock breaks
The stranger talks to the shared kernel directly, so a bug in the Linux kernel is a way into the whole house.

      
Runs
Snippets and whole projects with files and build steps; compiled simulators on the docker provider only.

      
For hostile code?
no, not alone Solid hardening, but standing on a shared foundation.

    

  

  

    
The spare room with a receptionist

    
Tier kernel · providers docker under runsc, once checked, agentsandbox under runsc

    

      
What it is
The same room, with someone at the door who takes every request. gVisor is Google's open-source stand-in kernel, written in Go (the programming language) and running as an ordinary program, that handles almost every request a container's code makes itself and uses only a short, locked-down list of real kernel calls. Docker starts a container under it through gVisor's runtime, runsc: the program docker calls instead of runc.

      
If the lock breaks
The stranger has to get past gVisor and then through the short list of calls gVisor still makes. Two bugs, in a row, and it is still your house.

      
Runs
The same as the spare room (compiled simulators on docker only), a little slower to start.

      
For hostile code?
yes The weakest room plimsoll calls good enough for hostile code on your own machine, when its startup check passes.

    

  

  

    
The cabin across town

    
Tier vm · providers e2b, dockercloud, agentsandbox under kata

    

      
What it is
A whole separate small computer. A microVM is a small virtual machine with its own kernel, started for one run and destroyed after it, kept apart from its neighbors by the processor itself. E2B and Docker Cloud Sandboxes are hosted services that rent them out by the second.

      
If the lock breaks
The stranger is in a throwaway machine with its own wiring. To go further it must break the hypervisor, the program that runs virtual machines and keeps them apart. On a hosted service, that machine is not yours.

      
Runs
Snippets and whole projects. Hosted E2B and Docker Cloud Sandboxes bill by the second; a Kata cluster you run yourself has infrastructure costs, without a plimsoll fee per run.

      
For hostile code?
yes The strongest wall plimsoll reports, still a statement from its checks rather than independent proof from the machine itself. A hosting company can read what it runs, so keep secrets out of the image.

The sign on the door


Every answer above says process. Where does that word come from? Not from an
inspector. It is plimsoll's statement, assembled from what it can check, and it is worth knowing
exactly what goes into it.





Think of a hotel. The hotel set the room up, checked at opening time that the deadbolt turns
and the window does not open, and prints "deadbolt" on your bill. That is worth a good deal more
than a brochure. It is still the hotel's word: nobody from outside inspected the lock this
morning, and nothing on the bill would change if someone swapped the lock after opening time.


The exact term for the inspector's certificate is attestation: cryptographic proof,
usually rooted in the hardware, of exactly what software a machine is running. plimsoll does not
have it, and says so wherever it reports a tier. Concretely:


    
  
  • kernel on docker rests on docker's own registration of the runsc runtime,
  checked by the preflight (the configuration check a provider runs at startup and on
  each readiness poll), plus the smoke test. The code says in so many words that this is not proof
  that the wall actually running is gVisor
  (sandbox/docker_preflight.go (EXTERNAL · source repo ↗)).
    • 
  
  • vm on E2B and Docker Cloud Sandboxes follows from which service it is. Their smoke
  tests prove the microVM behaves as promised, network blocked included; they do not prove a
  hypervisor is there.
    • 
  
  • process, the runs on this page, has no smoke test at all, because its walls are library
  code built into plimsolld and the same on every machine. The project's own tests prove the memory
  cap and the missing network functions, and at startup the wasm provider only reads its
  settings.
    • 
  
  • If the machine is changed after startup, or plimsolld itself is taken over, the sign can be
  wrong. A compromised server can state anything.
    • 



The full account, provider by provider, is
docs/isolation-tiers.md (EXTERNAL · official docs ↗).
If the attacks you must hold out against need attestation, no room here supplies it.




  
What you can do with the sign

  
Read it, and refuse to go in below the room you need. A request can name its floor, as the
  careful caller above did, and anything weaker is refused before a single line runs. The operator
  can set a floor for the whole server (SANDBOX_MIN_ISOLATION), and plimsoll's
  hardened mode, the startup setting PLIMSOLL_HARDENED=1, refuses to start
  unless every production safeguard is configured and refuses any run below kernel.
  The official clients also compare the tier that comes back with the floor that went out.
