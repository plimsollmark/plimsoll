Testing AI-written controllers in a sandbox

A controller is code that decides, many times a second, how to push on something physical: a cart, a motor, a power supply. When an AI writes one, "it compiled and the tests passed" says little. The honest test is what the code makes the physics do. Each page below is a recorded run where plimsoll ran the code in a sandbox against a simulator and kept the record, so you can replay exactly what happened.

  • A cart-pole, judged by its trajectoryAn agent's controller keeps a pole upright on a moving cart. Every 10 ms step is recorded and hashed into one fingerprint: run it twice, same fingerprint. The agent's first draft, with two terms of the wrong sign, drops the pole at 5.96 s.The physics oracle example
  • A swing-up controller in CCompiled to WebAssembly inside the sandbox, it swings the pole up from hanging and balances it: four scenarios, upright within 2.5 s in each, compared with the same law in JavaScript.The wasm-controller example
  • A buck converter in CA power supply that steps a voltage down holds 5 V out from 10 to 16 V in while its load halves at a moment it is not told. The C and JavaScript versions of the law give the same numbers, byte for byte.The wasm-buck example
  • The same run on every sandboxThe cart-pole run sent to every kind of sandbox the machine could reach. Every one produced the same fingerprint.The providers example
  • Eight simulatorsFrom a ship holding its heading to a satellite clock: each simulator runs a failing and a passing hand-written controller, and the page replays both.The simulation replay pages
  • Not a controller: an AI-written adapterCode that connects a platform to a simulated robot fleet's API, checked under faults, lost answers and refusals. In the recorded trial Claude Opus passed 6 of 6 scenarios, Claude Haiku and Claude Sonnet 5 of 6.The adapter example

What these do not show

  • That a simulator matches the real world. A matching fingerprint shows the same computation ran, not that the physics model is accurate.
  • Real hardware. Nothing here moves anything physical.
  • Large controllers. These are small laws, chosen so every run is easy to replay and check.
  • A sandbox's strength beyond what plimsoll states: each run's isolation tier is the sandbox's configuration plus a startup check, not hardware attestation.
